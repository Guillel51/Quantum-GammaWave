Build: `perf/integral-audit`, from `4600b7a` (v1.8.8). Everything below is either a number this
container produced or a check that ran; nothing here is a claim about a physical FM-1.

and correct the numerator's sum in one shared commit path.

## Memory

- app 558,688 B; package 610,898 B (`FM-1_982`); loader 7,742 B.
- RAM `.data+.bss` 96,452 / 98,304 (1,852 spare); pool 311,240 (9,248 spare).
- RAM code 22,500 / 24,576 (**2,076 spare**, +28 B against v1.8.8).
- `.hot_text` is the binding constraint: `mix_block` 7,674 B, `fx_run0` 3,984 B, `mix_part_m0`
  3,748 B. The setters were deduplicated into `qg_biquad_commit()` and two window checks became one
  unsigned compare each; no function was moved out of RAM, so latency is unchanged.

## Restore

`tools/fm1_restore.py --write --programmer file:PATH|flashrom:DEVICE`: erase 4 KiB, program 256 B,
read back each sector, then read the part back and compare. By default it starts at 0x4000 and keeps
the first 16 KiB (loader and boot header, unit-specific); `--include-head` is required to write them
and mandatory for `flashrom`, which cannot write a partial chip. Exit 8 on any difference, 2 when the
programmer fails, 5 when no programmer was given. `tests/restore_test.py` covers a blank simulated
part, a bit that does not program, a flashrom stand-in that lies and one that fails. **No hardware,
no physical unit, no verification that the FM-1 boots after a restore.**

## Integration (v1.8.9 branch `integ/v1.8.9`)

Two lines grew from `fa94ec5`: the EQ work (`perf/integral-audit`, 14 commits) and the
flash/OTA/core-1 hardening (`freebuff/6ae847e`, 1 commit). They are merged here; nothing from either
line was dropped. The only semantic collision was `tools/fm1_backup.py`: one side archived the
device's *objects*, the other read the *raw NOR*. Both kept, the musical one under
`tools/fm1_archive.py`, the raw one keeps the manifest `fm1_restore.py` validates. The merged
`project.c` guarded `flash_identify()` with `#if FELUCCA_FLASH`, which is what made the host and
emcc builds compile again after the merge.

## Signing and chip support

- `tools/fm1_keys.json` carries no production key: every package is refused, by design, until a
  custodian generates and protects a key outside this repository. `tools/fm1_release.py` is not
  enabled for production and no signed release was produced.
- `0x856014` stays writable, `0xB36014` stays read-only. No new chip support was added.

## Emulator, full-system and hardware

- WASM + native reference, Build ID and the Playwright browser test are host/emulator evidence only.
- 88,200 frames of the emulator are not a full-system run and not a unit.
- Physical recovery is documented, not demonstrated. No unit was flashed, erased or restored.
