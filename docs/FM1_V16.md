# M-VAVE FM-1 V16 — what this repository verified, and what it changed

Status: **host-verified, hardware pending.** Everything below that says "measured" was read from the
official file with this repository's own parser on a host. Nothing in this document was observed on a
physical unit: no transfer, no boot and no flash read on hardware happened here, and none is claimed.

---

## 2. The V16 container, measured

Parsed with the same code the installer uses (`Package` in `web/fm1pkg.js`; CRC16 0x1021/init 0,
JieLi ENC with key `0xFFFF` on the structures, SFC with chip key `0x980F` on the app area):

| | V15 (`FM-1_015`) | V16 (`FM-1_016`) |
|---|---|---|
| File size | 699 956 B | **718 196 B** |
| UFW entries | 2 | **8** (`flash.bin`, `info.log`, `isd_config.ini`, `ota.bin`, `script.ver`, `farg.cfg`, `blimit.bin`, `tail.bin`) |
| `flash.bin` at (file offset) | 1044 | **1044** |
| `flash.bin` size (flash image) | `0x93000` (602 112 B) | **`0xA9000` (692 224 B)** |
| `app_dir_head` / app base | `0x4000` | **`0x4000`** |
| `app.bin` offset | `0x4120` | **`0x4140`** |
| `app.bin` slot | `0x8E7BC` | **597 928 B (`0x91FA8`)** |
| `app_area_head` size | `0x8ED2B`-class | **`0xA4071`** (ends at `0xA8071`) |
| `ota.bin` (vendor loader) | 19 969 B | **19 969 B** |
| Chip key | `0x980F` | **`0x980F`** |
| Identity inside `app.bin` | `FM-1_015` | **`FM-1_016`** |

V16 also carries region descriptors this project has never used: `VM` at `0xBA000` (128 KiB), `PRCT`
over the whole flash, `SEQ64` at `0xDA000` (72 KiB), `BTIF` at `0xEC000`. And an extra app file,
`DX7.bin` (73 226 B, at `0x92267`), that V15 does not have.

**The consequence that shapes the install path:** V16's app area ends at `0xA8071`, past the write
window of this project's update loader (`LDR_APP_HI = 0x93000`). A package patched from the V16 file
would have its app truncated at `0x93000` by that loader. So the official V16 file is a **restore
target**, never the container a QG package is built from — and `buildFeluccaPackage()` refuses it by
name instead of producing a truncated image. QG packages keep this project's own layout
(`tools/fm1pkg_make.py`: app at `0x4120`, block ending ≈`0x8F000`, image `0x93000`), which lies
entirely inside the window.

## 3. What changed

### Identification
* `web/fm1pkg.js`: `STOCK_RELEASES` — both official releases, each pinned by file SHA-256, size,
  logical-image digest and the layout values above. `STOCK_IDENTITIES`, `isStockIdentity()`,
  `stockReleaseBySize()`, `stockReleaseByIdentity()`, `stockReleaseOf()`, `stockLayoutIssue()`.
* `web/fm1verify.js`: `FM-1_016` is **stock** (the firmware the installer may replace), not "another
  firmware". The report gains `stockRelease` and keeps `firmware.version = 16`, so V15 and V16 are never
  confused. `FM-1_017` and any other unread number stay `other`.
* `tools/fm1_install.py`, `tools/fm1_preflight.py`: both official digests are accepted as the
  return-to-stock package; `tools/check_package_identity.py` refuses `FM-1_016` as a custom package's
  identity, exactly as it refuses `FM-1_015`.

### Donor rule (installing from a stock unit)
* `web/fm1ota.js`: donors are `{15, 16}` — and the identity must agree with the firmware string the
  page knows; `FM-1_016` + "V15" is two claims and is refused. Unread stock numbers are still refused.
* The device identity the V16 vendor loader answers in update mode is `ota-FM-1_016`. It is **not** this
  project's loader (`isOurLoader` accepts 965 and the historical 900), so it is still reported and
  refused as `foreignloader`: nothing is ever served to the vendor's own update program.

### Transport
* `web/fm1ota.js` `requireProof()`: a package carrying this project's loader (`FELUCCA-LOADER-1`) is
  parsed and checked against `loaderWindowIssue()` **before any frame**: the flash image must reach
  `0x93000` and the app area must not cross it. A package that would be written truncated is refused.
  Official M-VAVE files carry the vendor's loader and are exempt — that is what allows a return to V16.
* `tools/fm1pkg_make.py`: the build now fails if its app area ever leaves the loader's window, so the
  guarantee is a property of the build, not of today's constants.

### Web Studio / page
* Stock-return section loads and validates **whichever official release the file is**, and uses that
  release's own digest and identity for the provenance token and the transfer (no more hardcoded
  `STOCK_V15_SHA256` / `FM-1_015`).
* Status line: `vStock` names the unit's identity dynamically; the four languages no longer claim V15
  when a V16 (or a V15) answered.

### Preserved
* Bootloader/head `0x0000–0x3FFF` is **never written**: the loader's write range starts at `0x4000`
  (`firmware/loader/loader.c` `FL_RANGE_OK`), so V16's SPL (`8f5228c2…`) survives a QG install.
* `ldr_flash_known()`, `FL_JEDEC_OK()` and the PR #86–#89 protections are untouched.
* Both writable parts (`0x856014`, `0xB36014`) are unchanged; read-only parts stay refused.
* No downgrade is performed automatically. Returning to stock is an explicit action with a pinned file.
* Nothing above `0x93000` is written by a QG install: on V16 that leaves `DX7.bin`'s tail, `VM`
  (`0xBA000`), `SEQ64` (`0xDA000`) and `BTIF` (`0xEC000`) untouched.

## 4. Install paths after this change

| Unit is running | Package | Path | Host-verified |
|---|---|---|---|
| V15 `FM-1_015` | QG `FM-1_965` | vendor updater stages our loader → app area `0x4000–0x92FFF` | yes (recognition, window, proof) |
| **V16 `FM-1_016`** | QG `FM-1_965` | same: V16's own updater stages our loader; our loader writes only the app window | **recognition + window + proof only; transfer not exercised** |
| QG `FM-1_965` | QG (update) | same loader | yes (host) |
| any | official V16 file | vendor's own `ota.bin` writes the vendor image; our host serves it and checks the pin | yes (pin + layout); transfer not exercised |
| any | official V15 file | as above | yes (pin) |

## 5. Pending physical verification (Phase 2)

These cannot be settled without a unit, and none is claimed here:

1. **Step 1 on V16.** That the V16 stock updater accepts a QG package and stages its `ota.bin`. The
   protocol is the same, the package shape is the one V15 accepted, but the V16 binary has not been
   exercised.
2. **`UPDATA_PARM` identity.** `firmware/src/ota.c` still hands the SPL the literal `ota-FM-1_015`.
   Whether the V16 SPL cares about that string is unknown; changing it without evidence could break
   the V15 path.
3. **V16 SPL booting the QG app area.** The QG image installs the V15-style app area (descriptors,
   `USR` at `0xEA000`, `BTIF` at `0xE9000`) over a V16 unit's `0x4000–0x93000`. Whether V16's SPL
   accepts that map, and whether it needs V16's `DX7.bin`/`SEQ64` descriptors, is unmeasured.
4. **V16 flash chip.** No JEDEC has been read from a V16 unit. The allowlist is unchanged; the loader
   still refuses an unknown part before erasing.
5. **Interrupted install and resume on V16**, and the post-install identity check
   (`FM-1_965` must answer after the reboot).
6. **Backup before writing.** M-Flasher must produce a verified full dump of the V16 unit first; the
   installer's "return to stock" path is the documented way back, and it has not been run.

Until (3) and (5) exist, a V16 install is **GO CONDITIONAL**: the software accepts the unit, refuses
anything it cannot prove, and writes only the app window — but no one has watched it boot.

## 6. Qué de V16 puede aprovechar Quantum GammaWave (y qué no)

V16 no es sólo un número: es otro firmware con otra arquitectura de voces y partes. Ocho **partes** no
son ocho voces, y veinte voces **compartidas** no son veinte por parte. Con lo que hay en este árbol:

| V16 | Quantum GammaWave hoy | Qué significa |
|---|---|---|
| 8 partes timbrales | 6 pistas (`NTRK`, `panic_req = (1u << NTRK) - 1`) | Pasar a 8 partes es trabajo de motor y de mezcla, no de instalador. Ninguna parte nueva existe por instalar sobre V16 |
| 20 voces totales compartidas | 10 por defecto, 8/10/12 seleccionables (`core.h VOICE_UCAP_N`, `docs/POLYPHONY_1.6.md`) | El techo actual es 12 y cuesta SRAM y CPU; 20 no está medido ni habilitado |
| Fine Tune ±100 cents por parte | hay detune por motor/voz en el modelo de parche | El rango por parte de V16 no está implementado |
| MIDI channel/nivel/pan/bend/glide por parte | MIDI por canal y expresión (CC11) por pista (`midi_control.c`) | La expresión y el panic ya existen; el resto por parte no |
| Secuenciador de 64 pasos | secuenciador propio (docs de fase 2/4) | Sin relación con el de V16 |
| 8 pistas × 8 columnas de arreglo | arreglista SLOOP de 6 pistas | No se adopta |
| 128 grupos de FX compartidos | bancos de FX propios | No se adopta |
| CC7 Master Volume / CC11 Expression | CC11 implementado; CC7 no verificado aquí | Revisar en fase 2 |
| ARP con MIDI externo, USB loopback, panic PLAY/STOP, RGB/backlight | panic existe; ARP/loopback/RGB son del firmware del fabricante | Fuera del alcance de esta fase |

En resumen: **esta fase hace que QG pueda instalarse sobre un V16 sin volver a V15 y pueda volver al
archivo oficial V16**. No convierte a QG en V16 ni le añade sus partes, voces o secuenciador; eso exige
medir el motor en la unidad, y las cifras del fabricante no son una especificación de este proyecto.
