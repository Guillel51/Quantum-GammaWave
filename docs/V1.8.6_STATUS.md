## What was wrong and what changed

### FX particles
`graph_drift()` passed `ui.frame / 16u` to the first FX graph. At the 60 Hz UI cadence that updates the
particle field only about 3.75 times per second, while the other sections pass `ui.frame`. The first
section now uses the same per-frame clock, with the same particle count and no per-frame allocation.
**Status:** IMPLEMENTADO / HOST TESTED. The effective update rate is 16× higher (3.75 → 60 logical
updates/s at 60 Hz); this is a timing property, not a claim of a measured end-to-end FPS counter.

### Splash
The boot screen has a bounded 425-step timeline (1.7 s at 4 ms), 200 changing frames, stars, parallax,
sparks, a logo reveal and a sweep. `tests/ui_render.c` renders it in every palette and checks the version
line and transitions. **Status:** IMPLEMENTADO / HOST TESTED.

### Note visualizer
Particles are keyed to active voices and their `gate`, `note` and velocity, with fixed storage, bounded
work and no audio-thread allocation. Chords, releases and repeated notes are covered by the UI render and
stress tests. **Status:** IMPLEMENTADO / HOST TESTED.

### Punch-In keyboard
White keys are 12 px with a 2 px gap; black keys are 9 px. The F3–G5/MIDI mapping, banks, latch mutes and
active states are unchanged. **Status:** IMPLEMENTADO / HOST TESTED.

### Master Biquad EQ
- `EQ_HZ[128]` spans 20 Hz–20 kHz and drives both the log X axis and the filter angle.
- Gain uses exact `10^(dB/40)` tables (`EQ_A_Q12`, `EQ_SQRT_A_Q12`), not the old linear approximation.
- Coefficients are Q24, preserving one 64-bit multiply per sample while removing the low-shelf DC
  cancellation; the stability margin is scaled to Q24.
- Response evaluation uses 64-bit squares and `fx_isqrt64`/`fx_ratio_q15`; no 64-bit division in the
  sample path.
- `tests/eq_sweep_test.c`: 480 corners, 0 residual tails, 0 bad coefficients; +24 dB peak `6054` Q8,
  −24 dB peak `−6102`, notch `−6144`, low shelf at 20 Hz/20 kHz `6102/−6`, high shelf `−12/6114`.
  Rapid gain/frequency/Q changes remain finite. Low/High Shelf, Peak, notch, HPF and LPF are exercised.
**Status:** IMPLEMENTADO / HOST TESTED. The graph is the computed response on a 20 Hz–20 kHz axis, not
the old 123–287 Hz approximation.

## Security and contingency

The installer refuses another model/identity, validates package size, structure and SHA-256 before writing,
stops on a lost device, and does not report success after a lost final ACK. `tests/installer_test.py` and
`web/test_ota.mjs` cover truncated/corrupt packages, wrong identity, interrupted writes and reconnects.
The architecture still has **no signed package, no anti-downgrade/replay protection, no A/B slot and no
independent recovery mode**. A power loss during the app write can therefore leave a non-booting unit until
the loader/USB path is used; that is documented, not presented as solved. No bootloader, partition or
low-level boot code was changed, and no physical FM-1 was flashed.
**Status:** protections IMPLEMENTADO / HOST TESTED; signed/rollback/recovery HARDWARE BLOCKED.

## Residual risks and pending work

- **HARDWARE TESTED: none.** Audio, latency, USB-MIDI, flash timing and recovery on a real FM-1 remain
  unverified; no physical unit was available.
- **Chromium console/FPS/Browser panel: BLOCKED.** The browser binary is installed, but the VM lacks
  `libnspr4`, `libnss3`, ATK/X11 and related libraries and `sudo` is blocked by `no-new-privileges`; the
  screenshot/console run did not start. HTTP artifact/version checks and host UI tests are the available
  evidence. The 3.75 → 60 logical updates/s figure is derived from the 60 Hz UI cadence, not a browser FPS
  measurement.
- Signature, anti-downgrade, A/B updates and a demonstrated recovery path are not implemented.
- The older `docs/V1.8_STATUS.md`, `docs/SYNC_1.7.md` and audit documents are historical and are not
  rewritten as current evidence.
